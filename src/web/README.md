# ReturnRight web app

React 19, Vite 8 and TypeScript, on Node 26.13.1. One app serves all four personas: customer, warehouse agent, finance reviewer and operations manager. The API (`src/api`) owns every business rule. This app only displays the API's decisions.

## Setup

```bash
cd src/web
npm install
cp .env.example .env.local     # optional; the defaults work with the API on :8000
npm run dev                    # http://localhost:5173
```

In dev, `/api/*` is proxied to FastAPI at `http://127.0.0.1:8000`, so the app needs no CORS setup.

## Scripts

| Command             | What it does                                                    |
| ------------------- | --------------------------------------------------------------- |
| `npm run dev`       | Dev server on :5173 with the `/api` proxy                       |
| `npm run build`     | Type-check, then production build to `dist/`                    |
| `npm run preview`   | Serve the production build                                      |
| `npm run typecheck` | TypeScript only                                                 |
| `npm run lint`      | ESLint                                                          |
| `npm run format`    | Prettier (write); `format:check` to verify                      |
| `npm run gen:api`   | Regenerate `src/api/schema.d.ts` from the API's `/openapi.json` |

Run `npm run gen:api` whenever the backend changes an endpoint or schema. Then call the API only through the typed client in `src/api/client.ts`.

## Structure

```
src/web/
├── index.html, vite.config.ts      Vite entry; /api proxy to FastAPI
├── eslint.config.js, .prettierrc   ESLint + Prettier (must pass before every commit)
├── .env.example                    VITE_API_BASE_URL, API_PROXY_TARGET (dummy values)
└── src/
    ├── main.tsx                    Mounts <App />
    ├── styles.css                  Design tokens (light + dark), focus ring, shared layout
    ├── app/                        App shell: providers, router, layout, 404
    ├── api/                        client.ts (openapi-fetch + auth header), queryClient.ts,
    │                               schema.d.ts (GENERATED by npm run gen:api)
    ├── auth/                       Staff session (JWT in sessionStorage), roles, RequireRole guard
    ├── components/ui/              Shared states: LoadingState, ErrorState, EmptyState, PageHeader
    ├── lib/                        format.ts: INR and dates (en-IN)
    └── features/                   One folder per persona; each holds pages/, components/, and api.ts when it has calls
        ├── returns/                Customer: order lookup, wizard + Stepper, QR label, StatusTimeline
        ├── warehouse/              Agent: scan or type the label code, grade A/B/C, accept or reject
        ├── finance/                Reviewer: approval queue for returns above 10,000 INR
        ├── dashboard/              Manager: return rate, top reasons, cycle time, flagged customers
        └── auth/                   Staff sign-in
```

## Conventions

- Feature code stays in its own `features/<area>` folder. Code moves to `components/ui` or `lib` only when a second feature needs it.
- Every data view shows a loading, an empty and an error state, using the shared components.
- Server data goes through TanStack Query hooks in `features/<area>/api.ts`. Never use `fetch` directly.
- Never retry a refund or payment action automatically. Mutations have `retry: 0`, and a retry reuses the same idempotency key.
- Every screen must work at phone width with the keyboard alone, with a visible focus ring. Use labels and roles that Playwright can find with `getByRole` and `getByLabel`.
- camelCase for variables, PascalCase for components and types.

End-to-end tests live in `tests/e2e/` (owned by QA). See its README.

## Rules

Synthetic or public data only. No client or confidential data in code, fixtures or prompts.
